How it works

Each run checks every package's recipe for changes. A package only moves through the pipeline when its recipe has changed, and each phase runs in its own container with only the secrets it needs.

  1. 1. Claude reviews the recipe

    Before anything is built, Claude reads the PKGBUILD and every other file the maintainer committed, looking for supply-chain threats such as hidden downloads, encoded shell commands, credential theft, sources pointing at unrelated sites, and install scripts that would run as root on your machine.

    • A pure version and checksum bump is compared against the last commit that passed and gets a quick review from Claude Haiku.
    • New packages, code changes and recipes too large to read in full get a deeper multi-pass review from Claude Sonnet.
    • A failing review holds the package. If the API is unreachable, the review is retried next run and nothing new is built.

    This is the only container with the Anthropic API key, and it never runs the recipe.

  2. 2. Build and Trivy scan

    The builder checks out exactly the commit Claude approved and re-verifies its hash, so a recipe cannot change between review and build. It imports the upstream signing keys the recipe declares, so makepkg can verify signed sources, then builds the package.

    Each package builds in its own throwaway sandbox inside a gVisor container, as an unprivileged user with a read-only system. A build sees only its own files: not other builds, not the packages waiting to be signed, and not the repository. Anything it leaves running is killed when it finishes. Dependencies come only from signed repositories and are removed after each build, so every build starts clean.

    Every built package is unpacked and scanned with Trivy for high and critical CVEs and for embedded secrets. Any finding, or a scan that fails to run, holds the package.

    The builder holds no API key and no signing key. A build that fails is not retried for 7 days unless the recipe changes.

  3. 3. Sign and publish

    A separate signer re-checks each package's SHA256 against what the builder reported, refuses anything that is not newer than the published version, then GPG-signs the package and the repository database.

    Packages that pacman no longer needs are deleted, and the status files on this page are rewritten at the end of every run.

    This is the only container with the signing key and the only one that can write to the repository.

Held packages

Holding fails closed. A held package keeps serving its last good build until a newer commit passes every check. The mirror never publishes an unreviewed or unscanned build.

Limits

Claude and Trivy are the only gates; no person reviews upstream changes. Builds share the builder's network, since sources have to download, so a malicious recipe that slipped past review could still reach the internet while it builds. It cannot reach other builds, the signing key or the repository.
